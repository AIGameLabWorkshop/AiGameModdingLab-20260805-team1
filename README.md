# AIで魔改造ワークショップ用リポジトリ

このリポジトリは、これからのAI時代に必要な「人の力」を育てることを目的とした教育／レクリエーション用のテンプレートです。

**目的**
- 参加者が「何を作るか」を考え、短い仕様に落とし込み、評価・改善する力を養います。
- 具体的には：アイデア発想、仕様化（要件定義）、優先付け、プレイテストでの評価、改良の繰り返し、そしてAIの出力を批判的に検証する力。
- 重要：実装方法（How）をAIに丸投げすることが目的ではありません。AIは補助ツールとして用い、最終的な判断・設計・評価は人が行います。

**対象**: 小学校高学年〜中学生、講師、運営スタッフ

## ワークショップの流れ
1. アイデア出し（付箋に手書きでOK）。短い一文で何を変えたいかを書きます。
2. 参加者はスプリント単位で1つ以上のアイデアを選び、短い仕様書（`Specs/TEMPLATE.md`）に記入します。
3. 講師は仕様を受け取り、AI支援ツールを補助にして実装（素早い試作を作成）します。実装は講師が行い、参加者とすり合わせます。
4. 試作を公開（例: GitHub Pages）して参加者がプレイテスト、フィードバックを得て、仕様やバックログを更新します。
5. 振り返り（何が面白かったか／改善点）、次のスプリントへ移行。

## 期待される育成スキル
- 発想力：遊びの着想を出す力
- 要件化：短く明確な仕様を書く力
- 批判的思考：AIの提案を評価・修正する力
- コラボレーション：意見をまとめ、実装を検証する能力
- 実験・反復：プレイテスト→改善を繰り返す姿勢

## ディレクトリ構成

下記はこのリポジトリに含まれるフォルダ／ファイル構成です（プロジェクトによって増減します）。

```
AiGameModdingLab/
├── README.md                    # このファイル
├── BrickBreaker/                # ゲーム実装プロジェクト
│   ├── css/                     # スタイルシート
│   ├── icons/                   # アイコンファイル
│   ├── js/                      # JavaScriptコード
│   ├── libs/                    # ライブラリ（Phaser等）
│   └── scripts/                 # ユーティリティスクリプト
└── Specs/                       # 仕様・要件管理
    ├── Assumptions/             # 前提条件・参考資料
    └── Samples/                 # 仕様書の実装例
```

**主要ファイル説明：**

- **BrickBreaker/**: ブロックブレーカーゲームの実装フォルダ
  - ゲームロジック（`js/phaser-game.js`）、UI/サウンド処理、レイアウト管理
  - PWA対応でオフラインでも動作
  
- **Specs/**: 仕様・要件管理フォルダ
  - ワークショップ参加者が機能要望を記入する仕様書
  - `TEMPLATE.md` をコピーして新機能の仕様を作成
