# Spec_08: レベル2から壁が爆発して消える

## 元の仕様書

| 項目 | 内容 |
|-----|------|
| **TRIGGER** | レベル2から壁がたくさん出てくる |
| **ACTION** | 一回あたった壁は爆発して消える、スコアは＋10 |
| **TEST** | スコアは10増えて、壁が爆発したらOK |

## 曖昧だった点と作った仮定

### 1. 「壁」の定義
**曖昧性：** 「壁」がどんなオブジェクトか明記されていない
- 既存のブロック種類（A/B/M）の一種か
- 新しいブロックタイプか
- スタティックなオブジェクトか

**仮定：**
- 新しいブロックタイプ「W」（Wall）として定義
- A/B ブロックと同じく矩形で、色で区別
- stage2 以上に配置される通常のブロック

**理由：**
- 既存のブロック種類（A/B/M）を活用しつつ、「壁」として新規タイプを追加するのが最小限
- 既存のブロック破壊ロジックそのままで対応可能

### 2. 「爆発して消える」の表現
**曖昧性：** 爆発エフェクトの詳細が不明確
- パーティクル？フラッシュ？スケール変更？

**仮定：**
- 既存のブロック破壊と同じ処理を実行
- 追加として、破壊時に小規模な爆発パーティクル（複数の小さな円が放射状に飛び散る）を演出
- 音は既存の `brickHit` SE をそのまま再生

**理由：**
- ワークショップの教育用ゲームなので、派手すぎないシンプルな演出
- 既存エフェクト（パーティクル）の活用で実装が最小限

### 3. レベル2「以上」か「限定」か
**曖昧性：** stage2 だけなのか、stage2 と stage3 の両方か

**仮定：**
- stage2 と stage3 の両方に壁（W）を配置
- stage1 には配置しない（レベルの進度に合わせて複雑さを増す設計）

**理由：**
- 既存の難易度設計（stage1 < stage2 < stage3）に合わせるのが自然
- 仕様の「レベル2から」は「2以上」と解釈

### 4. スコア加算のタイミング
**曖昧性：** スコア＋10 は壁の破壊時のみか、他の条件もあるか

**仮定：**
- W ブロック破壊時に固定で＋10 点
- A/B ブロックと同じくスコアは config.js で定義
- 複数の壁を破壊すれば、その数分加算される

**理由：**
- TEST「スコアは10増えて」=破壊1個で＋10 という直感的な解釈
- 既存のブロック得点システムと統一

## 実装内容

### 1. config.js - W ブロックタイプ追加

`blockTypes` に以下を追加：
```javascript
W: {
  // 壁（Wall）ブロックの色
  color: "0x8b4513",
  // 壁ブロックの耐久
  hitPoints: 1,
  // 壁ブロックを壊したときの得点
  score: 10
}
```

### 2. layouts.js - stage2 と stage3 に W ブロックを配置

**stage2** 例：
- 既存の stage2 レイアウトに W ブロックを戦略的に配置
- 複数の壁をゲーム進行の障害として機能させる

**stage3** 例：
- 最終ステージということで、より多くの壁を配置
- より複雑な配置パターン

### 3. render.js - 爆発エフェクト関数追加

**新規関数：** `createBrickExplosion(scene, x, y)`
- ブロック破壊位置から小さなパーティクルを放射状に飛び散らす
- 小さな円（3-5px）を 8-12 個放射状配置
- 速度：100-200 px/s でランダムな方向
- 重力はなし
- ライフスパン：400-600ms
- 色：オレンジ～黄色系（#ff8c00）

### 4. phaser-game.js - 破壊時の爆発演出

**修正箇所：** `onBallHitBrick()` 関数内、ブロック破壊時

ブロック破壊時に以下を追加：
```javascript
if (brick.getData("moving")) {
  // 既存処理
} else if (brick.getData("wallType")) {
  // W ブロックの場合は爆発エフェクト
  RENDERER.createBrickExplosion(this, brick.x, brick.y);
}
```

### 5. データマーク方式の検討

**案1：** レイアウトで「W」と文字指定 → config で type を見分け
→ **採用** 既存パターンに統一、シンプル

**案2：** brick.getData("type") で種類判別
→ 追加実装が必要だが、render.js で適切に判別

## 実装ノート

### 実装の詳細

1. **config.js**
   - blockTypes に W タイプを追加（色 0x8b4513 = サドルブラウン、得点10）

2. **layouts.js**
   - stage2：既存配置の M を一部 W に置き換え、複数の壁を配置
   - stage3：さらに多くの W を配置

3. **render.js**
   - `createBrickExplosion()` を実装
   - ParticleEmitter を使用（既存のボール効果と同じパターン）
   - 回転角度をランダムに設定して放射状演出

4. **phaser-game.js**
   - `onBallHitBrick()` で W タイプ判定
   - 爆発エフェクトを呼び出し

### エッジケースと制限事項

- **複数の壁を同時破壊：** ボール100個なので複数同時破壊の可能性あり。各破壊ごとにエフェクト＋スコア加算される（仕様に合致）
- **エフェクトの見た目：** シンプルなパーティクル。複雑なエフェクトは実装しない
- **パフォーマンス：** 爆発が多数発生する場合、ParticleEmitter はプール化しても問題ない範囲

### 修正したファイル

- `BrickBreaker/js/config.js` - W ブロックタイプ定義
- `BrickBreaker/js/layouts.js` - stage2, stage3 レイアウト修正
- `BrickBreaker/js/render.js` - 爆発エフェクト関数追加
- `BrickBreaker/js/phaser-game.js` - 爆発演出呼び出し

## テスト検証方法

### TEST 1: スコアが10増えるか
1. ゲーム開始 → stage2
2. ボールを壁（W ブロック）に当てて破壊
3. スコア表示が＋10 されることを確認

### TEST 2: 爆発演出が見えるか
1. ステージ2の壁を破壊
2. ブロック破壊位置から小さな粒が放射状に飛び散る演出が発生することを確認
3. 複数の壁を破壊して、複数回の爆発が見えることを確認
