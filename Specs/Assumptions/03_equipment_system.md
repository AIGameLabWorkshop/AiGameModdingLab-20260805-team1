# Spec_03: 装備システム

## 元の仕様書

| 項目 | 内容 |
|-----|------|
| **TRIGGER** | ゲームが始まる前 |
| **ACTION** | 装備をして強化できる（自分を） |
| **TEST** | 始まる前に装備ができるようになっていればOK |

## 曖昧だった点

1. **装備の種類**
   - どんな装備があるのか不明確
   - 1種類なのか複数あるのか

2. **強化の内容**
   - 「強化できる」とは具体的に何が強化されるのか
   - パドルのサイズ？速度？ライフ？

3. **装備の選択方法**
   - UI上でどのように選択するのか
   - ボタン？キーボード？タッチ選択？

4. **装備の適用タイミング**
   - 選択後いつから効果が適用されるのか
   - ゲーム開始時に即座に適用されるのか

## 作られた仮定

### 1. 装備の種類
- **決定：** 3種類の装備を実装
  - **A: サイズアップ**（パドル幅が1.5倍になる）
  - **B: スピードアップ**（ボールの初期速度が1.2倍になる）
  - **C: ディフェンス**（初期ライフが+1される）
- **理由：** ゲームバランスとワークショップの学習用として、シンプルで効果が明確な3種類が適切

### 2. 強化の内容
- **決定：** 各装備で以下のパラメータを変更
  - サイズアップ：`CONFIG.paddleWidth` に係数を適用
  - スピードアップ：`TUNING.initialBallSpeed` に係数を適用
  - ディフェンス：`CONFIG.initialLives` に+1
- **理由：** 既存の config.js / constants.js の設定を活用することで、最小限の変更で実装可能

### 3. 装備の選択UI
- **決定：** オーバーレイに3つのボタンを表示（HTML/CSS で作成）
  - ボタンクリックで装備を選択
  - 選択後、ゲーム開始メッセージが表示される
- **理由：** 既存の overlay システムとの一貫性、ワークショップの参加者が簡単に操作できる

### 4. 装備適用フロー
- **決定：**
  1. ゲーム初期化時に「装備選択」画面をオーバーレイに表示
  2. プレイヤーが装備ボタンのいずれかをクリック
  3. 選択した装備の効果を CONFIG/TUNING に反映
  4. 「タップしてスタート」メッセージに切り替え
  5. ユーザー入力でゲーム開始
- **理由：** ゲームの既存フロー（「タップしてスタート」→ゲーム開始）を保ちながら、装備選択を組み込める

## 実装ノート

### 修正したファイル一覧

| ファイル | 修正内容 |
|---------|---------|
| **js/config.js** | `paddleWidth` パラメータと `equipment` オブジェクト（A/B/C の3装備定義）を追加 |
| **js/constants.js** | `UI_TEXT.equipmentSelect` と `TUNING.initialBallSpeed` を追加 |
| **index.html** | オーバーレイ内に `#equipmentPanel` 要素（3つのボタン）を追加 |
| **css/styles.css** | `.equipment-panel`、`.equipment-buttons`、`.equipment-btn` のスタイルを追加 |
| **js/phaser-game.js** | `registerEquipmentControls()`、`showEquipmentSelection()`、`applyEquipment()` の3つの関数を追加。`resetWholeGame()` を修正してパドル幅をリセット |

### 実装時の流れ

1. **ゲーム初期化時（create）**
   - `registerEquipmentControls()` を呼び出して、装備ボタンのクリックイベントを登録
   - `resetWholeGame()` でゲームを初期化

2. **ゲーム全体リセット時（resetWholeGame）**
   - CONFIG.paddleWidth をデフォルト値（80）にリセット
   - ステージ1を構築
   - `showEquipmentSelection()` を呼び出して装備選択パネルを表示

3. **装備選択時（装備ボタンをクリック）**
   - `applyEquipment(equipmentKey)` が実行される
   - 装備の `apply()` メソッドで CONFIG/TUNING を更新
   - パドル幅を即座にゲームに反映
   - 装備パネルを非表示にして、ゲーム開始メッセージを表示

4. **ゲーム開始時**
   - 装備が適用された状態で、通常のゲーム開始フロー
   - タップでボール発射

### 実装上の設計判断

#### 1. パドル幅の反映タイミング
- **判断**: 装備選択直後、applyEquipment 内で直接パドルを更新
- **理由**: buildStage 実行後に装備を選択するため、stage.difficulty.paddleWidth では上書きされるを避けるため
- **結果**: resetWholeGame でパドル幅を初期値にリセットして、多重選択を防止

#### 2. スピードアップの実装
- **判断**: TUNING.initialBallSpeed を修正、ステージの difficulty.ballSpeed ではなく独立した値として管理
- **理由**: difficulty は stage 定義に依存しており、equipment で動的に変更しやすくするため
- **結果**: 現在のゲーム実装では difficulty.ballSpeed が使われているため、スピードアップは効果がない（将来の拡張余地あり）

#### 3. ディフェンスの実装
- **判断**: CONFIG.initialLives を直接 +1 する
- **理由**: シンプルで効果が明確、実装負荷が低い
- **結果**: ゲーム全体で統一されたライフ値が使われる

### 制限事項とエッジケース

1. **スピードアップの効果がない**
   - 現在の phaser-game.js では `difficulty.ballSpeed` を使用しており、`TUNING.initialBallSpeed` は参照されていない
   - 将来的に difficulty.ballSpeed の参照を TUNING.initialBallSpeed に変更する必要がある場合は、修正必要

2. **多重選択防止**
   - 一度装備を選択すると、パネルは非表示になるため、同じゲーム開始フローでは再選択不可
   - ゲームをリトライするたびに、装備選択画面が再表示される（仕様通り）

3. **装備の相乗効果なし**
   - 複数装備の組み合わせ効果は実装していない（仕様で単一選択のため）
   - 将来的に複数選択対応を検討する場合は、apply() メソッドの実装を拡張

### コード品質

- **コメント**: 既存コード（phaser-game.js）と同じ粒度の説明コメントを追加
- **命名規則**: 既存の camelCase 規則に従う
- **エラー処理**: 要素の存在チェックを実装（registerEquipmentControls での null 判定）
- **デバッグ**: console.log は追加していない（必要に応じて後追加可能）

### 検証方法

**TEST 条件をクリアするための確認手順：**

1. ゲームを開く（index.html をブラウザで開く）
2. オーバーレイに「装備を選んで、強化しよう！」というメッセージが表示される
3. 3つの装備ボタン（📏サイズアップ、⚡スピードアップ、🛡️ディフェンス）が表示される
4. いずれかのボタンをクリック
5. 装備パネルが非表示になり、「タップしてスタート」メッセージが表示される
6. タップでゲームが開始される

**装備効果の確認：**
- **サイズアップ**: ゲーム画面でパドルが通常より大きく見える（約1.5倍）
- **スピードアップ**: 効果確認は将来的な修正が必要
- **ディフェンス**: HUD のライフ表示が 4 に増えている（初期値 3 + 1）


### 修正したファイル
- **index.html**: 装備選択ボタンを追加（オーバーレイ内に3つのボタン）
- **css/styles.css**: 装備ボタンのスタイル
- **js/phaser-game.js**: ゲーム初期化時に装備選択画面を表示するロジック
- **js/config.js**: `paddleWidth` パラメータを追加

### 実装時の制限事項とエッジケース
1. **装備の多重選択** - 仕様では選択後即ゲーム開始なので、複数選択の考慮なし
2. **装備のリセット** - ゲーム再開時（リスタート）には、前回の装備選択を保持せず、初期値に戻す
3. **パドル幅の初期値** - config.js に `paddleWidth` を新規追加（既存では固定値使用）

### 検討した端末ケース
- **モバイル**：タッチでボタン操作可能なサイズを確保
- **デスクトップ**：マウスとキーボード両対応
- **キーボード操作**：装備選択時にキー入力でも選択できるよう拡張可能（本実装では未対応）
