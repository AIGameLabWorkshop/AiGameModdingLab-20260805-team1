# 仕様 spec_01.md - 曖昧性の明確化と仮定

## 元の仕様
- **TRIGGER:** スタートしてすぐ
- **ACTION:** ボール100個
- **TEST:** ボールの数が100個あればOK

## 曖昧だった点と作った仮定

### 1. ボール100個の初期配置位置
**曖昧性:** 仕様では「ボール100個」と書かれているが、どこに配置するか明記されていない

**仮定:** 
- 既存のボール初期位置（パドル上）を基準に、その周辺にボール100個をランダムに配置
- 配置範囲は画面内に収まるよう、パドル周辺の限定的な領域内

**理由:**
- ゲーム開始時に見えるボールが必要（画面外では意味がない）
- 100個全てがパドル上だと描画上問題
- 既存の`buildWorldObjects()`での初期配置パターンに合わせるのが自然

### 2. ボール100個が全て物理シミュレーション対象か
**曖昧性:** 100個のボール全てが独立したPhysicsボディを持つべきか

**仮定:**
- 各ボールは独立したPhysicsボディを持つ
- 各ボールが独立して移動・衝突・反射する
- パドル・ブロックとの衝突判定に全ボール参加

**理由:**
- TESTが「ボールの数が100個」という量的判定なので、機能的には独立していると考えるのが自然
- 既存の単一ボール実装に合わせて拡張するなら、配列化が最小限の変更

### 3. ボール同士の相互作用
**曖昧性:** 複数ボール間の衝突処理

**仮定:**
- ボール同士は衝突判定を持たない（ボール間の相互作用なし）
- 各ボールは独立してパドル・ブロックのみと衝突
- 理由：複数ボール管理の複雑さを避けるため

### 4. ライフ・スコア管理
**曖昧性:** 100個のボールでのゲームのエンドコンディション

**仮定:**
- ライフ管理は既存のまま（ボール落下でライフ-1）
- ただし100個全てが同時に落下するわけではない
- 各ボール落下時に1回のライフ減少

## 実装内容

### 修正ファイル
- `phaser-game.js` - ボール配列化、初期配置、衝突判定の更新

### 実装ノート

#### 1. ボール配列への変更
- `this.ball` → `this.balls` (配列)
- 各ボール同じ初期設定（半径、色、物理設定）

#### 2. 初期配置ロジック
```javascript
// パドル周辺にボール100個をランダムに配置
const ballStartY = CONFIG.paddleY - CONFIG.ballRadius - TUNING.ballRestOffsetY;
const ballSpreadRange = 60; // パドル周辺の配置範囲

for (let i = 0; i < 100; i++) {
  const offsetX = (Math.random() - 0.5) * ballSpreadRange;
  const offsetY = (Math.random() - 0.5) * ballSpreadRange * 0.5;
  
  const ball = this.add.circle(...);
  // 各ボールに物理ボディを設定
}
```

#### 3. 衝突判定の複数化
- `this.physics.add.collider(this.balls, this.paddle, ...)`
- `this.physics.add.collider(this.balls, this.bricks, ...)`
- Phaser の collider は自動的に配列全要素との判定を行う

#### 4. update() での処理
- 複数ボールでも既存の update ロジックはほぼ変わらない
- 画面外判定は全ボール対象に（別途ループが必要な場合）

## 実装の制限事項・エッジケース

1. **100個のボール同時管理による計算負荷**
   - 物理演算が100倍になる
   - 衝突判定も増加
   - ブラウザ環境では十分対応可能だが、古い端末では注意

2. **描画パフォーマンス**
   - 100個の円の描画
   - グロー・ハイライトエフェクトは最初のボール（balls[0]）のみに適用（パフォーマンス重視）
   - 100個全てにエフェクト付与すると処理が重くなりすぎる

3. **複雑なゲームロジック**
   - ボール1個の想定からボール100個へ
   - `ballHitBrick` のカウントが100倍になる
   - スコア計算なども確認が必要

## 実装の詳細

### ステップ1: `phaser-game.js` の修正

#### 1-1. constructor の修正
- `this.ball = null;` → `this.balls = [];`
- ボール単一管理から配列管理へ

#### 1-2. buildWorldObjects() のボール作成処理
```javascript
// ボール100個を配置する。
// 初期位置はパドル周辺の領域内にランダムに配置。
const ballStartX = CONFIG.width / 2;
const ballStartY = CONFIG.paddleY - CONFIG.ballRadius - TUNING.ballRestOffsetY;
const ballSpreadRangeX = 80; // X方向の配置範囲
const ballSpreadRangeY = 40; // Y方向の配置範囲

for (let i = 0; i < 100; i++) {
  // 各ボールの初期位置をランダムにずらす
  const offsetX = (Math.random() - 0.5) * ballSpreadRangeX;
  const offsetY = (Math.random() - 0.5) * ballSpreadRangeY;
  const x = Phaser.Math.Clamp(ballStartX + offsetX, CONFIG.ballRadius, CONFIG.width - CONFIG.ballRadius);
  const y = Phaser.Math.Clamp(ballStartY + offsetY, CONFIG.ballRadius, CONFIG.height - CONFIG.ballRadius);

  // ボールを円として作る
  const ball = this.add.circle(x, y, CONFIG.ballRadius, CONFIG.colors.ball);
  // false を渡すと dynamic body（速度で動く体）になる。
  this.physics.add.existing(ball, false);
  // 重力はこのゲームでは使わない。
  ball.body.setAllowGravity(false);
  // 画面端に当たる判定を有効化。
  ball.body.setCollideWorldBounds(true);
  // 反射係数1 = 速度をほぼそのまま反転させる。
  ball.body.setBounce(1, 1);

  // 配列へ追加
  this.balls.push(ball);
}

// 最初のボールにだけエフェクト付与（パフォーマンス考慮）
if (this.balls.length > 0) {
  const ballEffects = RENDERER.createBallEffects(this, CONFIG, this.balls[0]);
  this.ballGlow = ballEffects.ballGlow;
  this.ballSpecular = ballEffects.ballSpecular;
}
```

#### 1-3. 衝突判定の設定
```javascript
// Phaser の collider は自動的に配列全要素との判定を行う
this.physics.add.collider(this.balls, this.paddle, this.onBallHitPaddle, null, this);
this.physics.add.collider(this.balls, this.bricks, this.onBallHitBrick, null, this);
```

#### 1-4. resetBallToPaddle() 関数
- 全ボールをループで処理
- 各ボールをパドル上の初期位置に戻す

#### 1-5. launchBall() 関数
- 各ボールに独立した速度を設定
- 左右方向は各ボール独立でランダム決定
- 上下速度にも微小なランダム変動を加える（ばらつき効果）

#### 1-6. handlePaddlePassThroughFallback() 関数
- 全ボール対象にパドル抜け判定を実施

#### 1-7. update() 関数
- ready フェーズ：全ボールをパドルに追従させる
- playing フェーズ：全ボールのパドル抜け判定＋画面下落下判定
- 落下判定：各ボール個別に実施

### ステップ2: `render.js` の修正

#### 2-1. syncActorDecorations() 関数
- `scene.ball` → `scene.balls && scene.balls.length > 0` に変更
- 最初のボール（balls[0]）のグロー・ハイライトのみ同期
- 100個全てに同期すると処理負荷が高すぎるため、最初のボールのみ

## 実装時の決定ポイント

### なぜ100個のボール全てにエフェクトを付けないのか？
- Phaser の描画処理：100個の円＋100個のグロー＋100個のハイライト = 300オブジェクト の描画が必要
- 古いブラウザや低性能端末ではフレームレート低下の原因
- 最初のボール（主軸になるボール）のエフェクトのみ表示することで、ゲーム感をある程度保持しつつ性能を確保

### なぜボール発射時に速度にばらつきを持たせるのか？
- 100個のボール全てが全く同じ速度だと、単なる集団移動に見えて面白くない
- 各ボール独立の方向＋微小な上下速度変動により、「拡がり」「躍動感」を演出
- launch 時の垂直速度に 0.8～1.2倍の乗数を加える（verticalVariation）

## テスト検証方法

1. **ボール100個の配置確認**
   - ゲーム起動時に、パドル周辺にボールが密集して見える
   - ブラウザの開発者ツール（F12）で scene.balls.length を確認
   - 期待値：100

2. **ボール発射動作確認**
   - スペースキーまたはタップで発射
   - 全ボールが同時に動く（各ボール独立の方向）
   - 画面各方向へ飛散する様子を観察

3. **衝突判定確認**
   - ボールがブロックに当たるとスコア増加
   - スコア増加量 = （衝突したボール数）×（ブロックの得点）
   - 100個のボール全てが同時にブロックに衝突することもある

4. **ボール落下判定**
   - 画面下へ落ちたボールはライフが1回減少
   - 複数ボール同時落下でもライフ減少は発生ごと（100個全て落ちると最大100回減少）

## 既知の制限・改善案

### 制限事項
1. グロー・ハイライトが最初のボールのみ表示
2. 複数ボール時のカメラ動作が既存実装のままで最適化なし
3. ボール100個で画面が見づらい場合がある

### 今後の改善案
1. ボール数を設定値化 (CONFIG.ballCount = 100)
2. エフェクトの選別ロジック改善（視野内のボールのみエフェクト）
3. ボール群の自動グループ化・衝突最適化
