# 仕様 spec_07.md - 曖昧性の明確化と仮定

## 元の仕様
- **チーム名:** ぬっちゃん
- **TRIGGER:** レベル３の途中から、ボールが1~2個出てくる
- **ACTION:** 途中から入ったボールも、おちたらライフが1つずつ消える、スコア＋２０
- **TEST:** スコア＋２０ふえて、ボールが1〜2個増える

## 曖昧だった点と作った仮定

### 1. 「途中から」のタイミングが不明
**曖昧性:** 「途中から」が何時点を指すのか不明瞭
- ステージ開始時？
- ゲーム内の特定の条件？
- 時間経過？

**仮定:**
- ステージ3でボールが既に飛んでいる状態での「途中」
- トリガー：ブロック破壊が進んだ時点（全ブロック数の50%が破壊されたとき）
- 最もゲーム的に自然で、プレイヤーが目標達成の進捗を感じやすい

**理由:**
- 既存コードが `remainingBricks` でブロック残数を管理しているため
- 破壊進行度の判定はコード内に実装済みのパターンに合致
- 時間経過ではゲームスピードに依存してしまう問題を回避

### 2. ボール「1～2個」の具体的な数
**曖昧性:** 毎ゲーム固定で2個？それとも毎回1個または2個のランダム？

**仮定:**
- ステージ3では、ブロック50%破壊時に「1個のボール」を追加
- 毎ゲーム実行時に固定で1個（ランダムに選ぶ仕様ではなく）
- ボール100個管理の仕組み上、配列への追加は容易

**理由:**
- 最小限の実装で仕様を達成
- ゲームバランスの調整が容易（1個なら実績は明確）
- spec_07の「1〜2個増える」は「最大2個」という上限指定と解釈

### 3. スコア「+20」のタイミング
**曖昧性:** ボール追加時に一度だけ？それとも継続加算？

**仮定:**
- ボール追加時に「一度だけ」+20点を加算
- 追加ボール出現時のトリガーで加算

**理由:**
- 「スコア+20」は事象に紐付いた報酬として自然
- 継続加算だと、ボールが画面に存在する限り点数が増え続ける不自然な仕様
- TEST条件「スコア+20ふえて」が「差分20」という解釈と一致

### 4. 「ボールが1～2個増える」と「途中から1～2個出てくる」の関係
**曖昧性:** ステージ3で一度に複数個追加？それとも複数回トリガー？

**仮定:**
- ステージ3では追加ボールは1回だけ発動
- ブロック50%破壊の時点で1個のボール追加
- 「1～2個増える」は「最大2個の可能性」という上限指定

**理由:**
- 仕様書が「1～2個」という曖昧な表現なので、最も確実な単一実装
- 複数回トリガーするとゲームバランスが不安定になる
- 既存のボール100個管理システムとの整合性

### 5. ボール落下時のライフ減少
**曖昧性:** 追加ボールが落ちた時の動作

**仮定:**
- 既存の `handleLifeLost()` メカニズムを活用
- 追加ボールも含めた全ボール配列の統一管理
- 各ボール落下時に個別にライフ-1

**理由:**
- 既存コードが100個のボール配列管理をしているため
- 追加ボールも配列に登録することで自動的に判定される
- 「落ちたらライフが1つずつ消える」という要件を満たす

## 実装内容

### 修正ファイル
- `phaser-game.js` - ステージ3追加ボール管理、発動条件、スコア計算の追加

### 実装ノート

#### 1. コンストラクタに追加ボール管理フラグを追加
```javascript
// ステージ3 追加ボール管理（spec_07対応）
this.extraBall = null;         // ステージ3の追加ボール参照
this.extraBallSpawned = false; // 追加ボール発動済みフラグ
```

#### 2. buildStage() 内でステージ3の追加ボール準備
```javascript
// ステージ3のための追加ボール準備（spec_07対応）
if (stageIndex === 2) {
  // パドル周辺にボールを1個作成
  const ballStartX = CONFIG.width / 2;
  const ballStartY = CONFIG.paddleY - CONFIG.ballRadius - TUNING.ballRestOffsetY;
  const offsetX = (Math.random() - 0.5) * 60;
  const x = Phaser.Math.Clamp(ballStartX + offsetX, CONFIG.ballRadius, CONFIG.width - CONFIG.ballRadius);
  
  this.extraBall = this.add.circle(x, y, CONFIG.ballRadius, CONFIG.colors.ball);
  // 物理ボディ設定
  this.physics.add.existing(this.extraBall, false);
  this.extraBall.body.setAllowGravity(false);
  this.extraBall.body.setCollideWorldBounds(true);
  this.extraBall.body.setBounce(1, 1);
  // ボール配列に登録
  this.balls.push(this.extraBall);
}
```

#### 3. onBallHitBrick() 内でステージ3 追加ボール発動判定
```javascript
// ステージ3でブロック破壊が50%に到達したら、追加ボールを有効化
if (this.stageIndex === 2 && !this.extraBallSpawned) {
  const totalBlocks = this.getStage(this.stageIndex).blockLayout.flat().filter(cell => cell).length;
  const destroyedBlocks = totalBlocks - this.remainingBricks;
  const destroyedPercent = destroyedBlocks / totalBlocks;
  
  if (destroyedPercent >= 0.5) {
    this.extraBallSpawned = true;
    this.score += 20;
    this.updateHud();
    sfx.play("powerup");  // パワーアップ音
  }
}
```

#### 4. buildStage() 内で前ステージの追加ボール処理を削除
```javascript
// ステージ3 追加ボール管理をリセット（spec_07対応）
this.extraBallSpawned = false;
if (this.extraBall) {
  this.extraBall.destroy();
  this.extraBall = null;
}
```

## 実装の制限事項・エッジケース

1. **複数ボール管理による負荷**
   - ボール100個 + 追加1個 = 最大101個の物理計算
   - ブラウザ環境では十分対応可能だが、最小限設計

2. **ブロック50%破壊トリガーの選択**
   - 「途中から」の明確な基準がないため、ゲーム全体の半分まで進行した時点を採用
   - 実際のゲーム中、プレイヤーの進捗感を引き出すバランス

3. **ステージ3のみの制限**
   - 仕様がステージ3限定なため、他のステージでは追加ボール機能は動作しない
   - ステージ変更時に追加ボール状態を完全リセット

4. **既存ボール100個との並行管理**
   - 追加ボールもボール配列に登録されるため、既存の落下判定・衝突判定が自動的に適用
   - 新たなバグやエッジケースが発生しにくい設計

## TEST検証

### 要件 1: スコア+20増加
- ステージ3でブロック50%破壊時にスコア20点が加算される
- HUD上のスコア表示が+20される

### 要件 2: ボール1～2個増加
- ステージ3開始時にボールが100個（既存）
- ブロック50%破壊時にボールが101個に増加（+1個）
- ゲーム画面上で追加ボール1個が見える

### 要件 3: 落下時のライフ減少
- 追加ボール（101番目）が画面下に落ちたらライフ-1される
- 既存ボール同様に機能することを確認

### 検証手順
1. ステージ3を開始
2. ブロックを約半分破壊する
3. スコアが+20されたことを確認
4. ボール数が1個増えたことを確認
5. 追加ボールを故意に落下させてライフが減ることを確認
